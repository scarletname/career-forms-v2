# Конструктор форм отклика

Сервис для карьерной платформы: менеджер сам собирает форму отклика на стажировку или мероприятие, публикует её по ссылке, студент заполняет, менеджер смотрит заявки и статистику заполнения.

Ключевые решения, допущения и что сознательно не сделано — в [DECISIONS.md](DECISIONS.md).

## Запуск

Нужен Node.js 20 или новее.

```bash
npm install
npm start
```

- Админка: http://localhost:3000/admin
- Публичная форма: по ссылке вида `http://localhost:3000/f/<id>`, которая появляется в админке после публикации
- Порт меняется через переменную окружения `PORT`
- Данные хранятся в `data/db.json`, файл создаётся при первом сохранении. Чтобы начать с чистого листа — удалите папку `data`.

## Как пройти основной сценарий

1. В админке нажать «+ Новая форма», добавить вопросы, сохранить.
2. «Предпросмотр» — посмотреть форму глазами студента.
3. «Опубликовать» — появится ссылка для студентов.
4. Открыть ссылку в другом браузере или в режиме инкогнито и отправить заявку.
5. В админке открыть вкладки «Ответы» и «Статистика».

## Структура

```
server.js            запуск сервера, маршруты страниц, обработка ошибок
src/storage.js       хранение в JSON-файле (запись через временный файл)
src/validation.js    проверка схемы формы и ответов студента
src/api.js           API админки: формы, статусы, ответы, статистика
src/public-api.js    API для студента: форма, отправка ответа, события аналитики
public/admin/        админка (список форм, конструктор, ответы, статистика)
public/form/         публичная форма
```

## Что проверено вручную

- Запуск по `npm install && npm start`, смена порта через `PORT`.
- Сохранение формы с ошибками: сервер возвращает список всех ошибок, форма не сохраняется.
- Повторное сохранение формы не меняет id вопросов и вариантов (от этого зависят аналитика и снимки).
- Переходы статусов: черновик не открывается по публичной ссылке (404), вернуть опубликованную форму в черновик нельзя, закрытая форма не принимает заявки (409).
- Ошибки ответа студента показываются у конкретных полей: формат email, несуществующая дата (31 февраля), удалённый вариант ответа, обязательные поля, согласие.
- Черновик студента восстанавливается после перезагрузки страницы и удаляется после успешной отправки.
- Переименование вопроса не меняет уже полученные заявки — в них остаётся текст на момент отправки.
- Воронка: повторное открытие в том же браузере не увеличивает число открытий; «место ухода» считается по полю, на котором студент был последним.
- HTML в тексте вопроса или ответа выводится как текст, а не как разметка.
- Конструктор в админке на ширине телефона (375px) без горизонтальной прокрутки.

## Работа с AI

Решение сделано вместе с AI-ассистентом (Claude Code). Полные логи диалогов предоставлю по запросу.

**Что делала я:**
- сформулировала задачу, границы MVP и список того, что не делаю (DECISIONS.md);
- принимала решения в спорных местах: поведение при редактировании опубликованной формы, удаление полей, формат ссылки, способ подсчёта открытий, определение «начала заполнения», строгая проверка при сохранении, отказ от удаления форм и от приоритизации задач;
- просматривала код, собирала проект по шагам и коммитила, запускала проверки API;
- записывала решения и известные ограничения в DECISIONS.md.

**Что делал AI:**
- критиковал первую версию DECISIONS.md и задавал вопросы по допущениям;
- предлагал варианты решений с плюсами и минусами;
- писал код сервера, API и проверок; код публичной формы и админки написал целиком и проверил в браузере на копии проекта;
- прогонял проверки и разбирал ошибки.

**Где пришлось поправлять результат:**
- расхождение кода и документа: событие фокуса засчитывалось как «начало заполнения», хотя по DECISIONS это первое изменение поля — код приведён к документу;
- тестовая команда от AI падала до отправки запроса — ошибка оказалась в самой команде, а не в сервере;
- защита от XSS изначально была описана только для текстов вопросов, хотя главный риск — ответы студентов, которые видит менеджер;
- формулировка проблем в DECISIONS.md: вместо потребностей пользователей — проблемы из задания и то, какая часть решения какую закрывает.
